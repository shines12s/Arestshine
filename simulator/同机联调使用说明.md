# OriginClient 同机联调使用说明

本文说明在同一台设备上运行 `OriginClient` 和
`OriginClientProtocolSimulator` 时，如何接收模拟器发送的 MQTT 和 UDP 数据。

## 目录结构

```text
/home/lyu/Client/
├── OriginClient/
└── OriginClientProtocolSimulator/
```

同机通信使用回环地址 `127.0.0.1`，不使用 `192.168.12.1` 或其他局域网地址。

## 地址配置

### 模拟器

`config.yaml` 中保持以下关键配置：

```yaml
mqtt:
  host: 127.0.0.1
  port: 3333

udp_video:
  target_host: 127.0.0.1
  target_port: 3334
```

含义如下：

| 数据 | 地址 |
| --- | --- |
| MQTT Broker | `127.0.0.1:3333` |
| UDP 图传目标 | `127.0.0.1:3334` |
| 模拟器控制台 | `http://127.0.0.1:9130` |

### OriginClient

在 OriginClient 的网络设置中填写：

| 设置项 | 值 |
| --- | --- |
| IP 地址 | `127.0.0.1` |
| Broker 地址 | `mqtt://127.0.0.1:3333` |
| MQTT 端口 | `3333` |
| UDP 监听端口 | `3334` |
| UDP 编码 | `H.265` 或 `自动检测` |

IP 地址必须填写 `127.0.0.1`。OriginClient 会使用这个地址作为 UDP 来源过滤地址；如果仍填写 `192.168.12.1`，模拟器发出的本机 UDP 数据可能会被过滤掉。

OriginClient 的 Client ID 必须是有效的机器人 ID，例如 `1`。模拟器默认期望 Client ID 为 `1`，但只提示不匹配，不会拒绝连接。

## 启动步骤

### 1. 启动模拟器

```bash
cd /home/lyu/Client/OriginClientProtocolSimulator
./start.sh
```

启动后打开：

```text
http://127.0.0.1:9130
```

确认模拟器 GUI 中显示：

- MQTT Broker 已在线
- MQTT 监听地址为 `127.0.0.1:3333`
- 视频文件路径有效

### 2. 启动 OriginClient

在另一个终端运行：

```bash
cd /home/lyu/Client/OriginClient
npm run tauri -- dev
```

### 3. 连接 MQTT

在 OriginClient 网络设置中填写地址后，选择机器人并点击 MQTT“连接”。

连接成功后，模拟器 GUI 的“已连接客户端”列表中应出现对应 Client ID，例如：

```text
1
```

然后在模拟器 GUI 中点击“启动推荐场景”或发送单条消息，OriginClient 即可接收 MQTT Protobuf 数据。

### 4. 接收 UDP 图传

确认 OriginClient 的 UDP 图传接收已经启动，并且监听端口为 `3334`。

模拟器的 `udp_video.start_on_launch` 默认为 `false`。如果模拟器启动后没有自动发送视频，需要在模拟器 GUI 中点击启动图传。

## 验证命令

检查模拟器 MQTT 端口：

```bash
ss -ltnp | grep ':3333'
```

正常情况下应看到：

```text
127.0.0.1:3333
```

检查 OriginClient 是否监听 UDP 端口：

```bash
ss -lunp | grep ':3334'
```

检查模拟器当前状态：

```bash
curl http://127.0.0.1:9130/api/state
```

其中应关注：

- `broker.running` 是否为 `true`
- `broker.clients` 是否包含 OriginClient 的 Client ID
- `video.running` 是否为 `true`
- `video.stats.frames` 和 `video.stats.packets` 是否持续增加

## 常见问题

### MQTT 连接失败

确认 OriginClient 使用的是：

```text
mqtt://127.0.0.1:3333
```

不要使用：

```text
mqtt://192.168.12.1:3333
```

同机模式下，模拟器只监听 `127.0.0.1`，而不是 `192.168.12.1`。

### 模拟器没有显示客户端

确认以下项目：

- OriginClient 已选择机器人
- Client ID 是数字，例如 `1`
- MQTT 地址和端口正确
- 模拟器 GUI 显示 MQTT Broker 在线
- 没有其他程序占用 `3333` 端口

### MQTT 已连接但没有消息

Broker 启动后不会自动发布全部协议数据。请在模拟器 GUI 中点击“启动推荐场景”或“发送一次”。

### UDP 没有画面

确认以下项目：

- OriginClient 的 IP 地址填写 `127.0.0.1`
- UDP 监听端口为 `3334`
- OriginClient 已启动 UDP 图传接收
- 模拟器视频文件存在
- 模拟器视频发送状态为运行中
- `packet_loss_percent` 保持为 `0`

### 是否需要 sudo

同机使用 `127.0.0.1:3333` 和 `127.0.0.1:3334` 不需要 `sudo`，也不需要修改 OriginClient 源码。
